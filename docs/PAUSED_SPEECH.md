# Speech while an AirPlay source is paused

A phone can retain its admitted zone source while sending no music PCM. Speech still uses OwnTone's common output converter and transports, without adding phone frames, changing program position P, seeking, pausing, reconnecting or inventing a music source.

Recent flowing music uses the existing observe/BEGIN handshake and existing late speech mix. A paused or never-produced phone first prepares the exact selected output sessions. OwnTone emits an output-only zero bed on its existing player timer and mixes the independently admitted voice over it. A source admitted before its first music packet can use this same timer without starting a fake player queue/session.

The output-only bed has its own clock O. Each write ends no later than monotonic T captured before checking that input is empty. Normal tick jitter retains sample continuity; a missed tick starts the next empty bed in the preceding player interval. A fresh post-peek clock suppresses a stale write after a mutex/scheduling stall. The bed occupies no future output horizon: any first music P accepted as genuinely future by the unchanged native admission check is strictly after O. A packet arriving immediately after the empty peek with only one millisecond of original lead remains admissible. Real queued music anchors suppress the bed and are never rebased.

OwnTone outputs add their existing route buffer B to the bed timestamp. The supported configuration already has a minimum local B of 40 ms. Bed timestamp age is bounded to 30 ms before output encoding, leaving existing transport processing lead without increasing the configured music or speech buffer. Existing speech priming and packet expiry stay unchanged; the five-second startup limit is a maximum setup deadline, not an inserted playback delay.

Voice admission/retirement carries the exact speech identity and captured source admission fields. Music FLUSH or END changes the current source generation but does not revoke the separately admitted voice. END's existing delayed output stop is canceled only for selected ready transports with an actual admitted voice or valid tail. When the last voice bed ends and the source is still exactly idle, delayed cleanup is restored only for the same selected output sessions. A retained paused phone stays warm.

The maintained `bed1` patch changes only configure metadata, the player orchestration/mix seam and the strict nine-field speech readiness parser. The parser now allows prepare/ready/release on an exact nonzero phone source; all room, launch, source and speech fences remain in the player. An idle source still cannot use the music-only observe action. The original media owner, receive TTL, peer credentials, payload validation and media retirement module bytes are unchanged.

The backend recipe applies the bed after the independently reviewed balance and native transition layers. It pins manifest argument 29 and requires the exact `balance1-transition1-bed1` version. The final guard checker verifies sixteen exact player bodies and the whole parser, then privately reverses only the pinned bed and transition patches and runs the immutable historical owner/readiness/media/auth validation. It does not permit a generic bypass for composed sources.

Software evidence uses actual extracted OwnTone timer, playback, source arm/seal, readiness and voice functions plus the actual receive/mix/retirement module. Cases include a pause exceeding 30 seconds; no initial music PCM; pause→voice→resume at original P; FLUSH generation changes while voice continues; music END with voice continuing beyond the ten-second delayed stop; natural tail retention and exact cancellation; a one-millisecond post-peek music arrival; and 20,000 jittered ticks. The same pre-bed source reproduces the original player and JSON preparation refusals. These tests control hardware callbacks and the transition deadline seam; real encrypted ingress, full Linux linking, real FFmpeg conversion and audible speaker acceptance are separate qualification steps.
